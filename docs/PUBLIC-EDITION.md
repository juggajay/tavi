# Making and reviewing a public edition

The working repository stays private, including its history. A public release is a fresh file tree; it is not a branch of that repository. Capability changes reach the public repository when a maintainer repeats the export, reviews it and pushes the separate public history. No job automatically publishes anything.

In the private source, read `scripts/public/contents.mjs`. It selects the complete `src`, `ui`, `box`, `desktop`, `web`, `render` and `drawings` trees, excluding generated output, dependencies, data, caches, account settings and the artwork review record. Selected package files, TypeScript settings, Python requirements, line-ending rules and local run/build helpers are included. Public-only files replace the working README and guides. The private exporter and its private list do not ship.

The selected tests are: calc, cards, guard-core, guard-fence, guard-route, hq-engine-parser, hq-doing-words, hq-rows, hq-cards-storage, hq-bots, hq-memory-scope, items, migrations, model-geometry, model-recipes, page-shape, palette, sketch and time. Their names end in `.test.ts` under `tests/unit`. They exercise calculation, saved data, safety behavior with fake runners, parsing, memory separation, geometry and page shapes. They need no outside network or real Linux space; any local test listeners close within their test. The support files are the isolation helper, sequential runner, fake Hermes helper and its made-up sign-in-error stream.

Other tests are not selected because they have not been reviewed for independence from private fixtures, source documents, local installed programs, live services or full browser/device setup. In particular live and UI trials, rendering needing external programs, linked-computer checks, carry-over checks and the exporter tests in the private source are not public proof. A small reviewed set is preferable to copying personal test examples and pretending the result is portable. Expand the written selection as those tests are reviewed.

The only automatic cleaning rules are exact replacements of the earlier displayed app name with Tavi, and the old package description with a general description of the personal AI system. Each rule must match at least once in a full build. Private examples, hard-coded user folders and personal defaults need source review rather than broad substitutions. Internal compatibility names remain where changing them could break data or integrations. Nested stage notes in the guard, screen source and screen setup README files stay out. The public change list is also placed at the older v2 and v3 reader paths by the tool-list command, so existing readers receive the rewritten list. The Siri guide is rewritten at its existing reader path.

The reviewer supplies `scripts/public/private-words.txt` in the private source. Its example uses whole words or phrases, one per line, with optional `re:` patterns. No real list is supplied in the release. The exporter refuses without a nonempty list and excludes every file whose name starts with private-words. The local ignore file also excludes the real list and last-made record. Do not put real private patterns into the example.

Run `node scripts/public/tools.mjs` to refresh TOOLS, then `node scripts/public/make.mjs --check`. The check builds a temporary tree outside the working repository and removes it even after failure. Reports identify file, line and rule without printing the private matching text. Every selected file, including binary bytes and wide text, is scanned for list entries, contact details, user folders, private machine/network names and common key formats. Public example email domains and narrowly identified firewall range constants are allowed; arbitrary exceptions are not.

After a clean scan, the copied tree runs both type checks and the shipped unit tests one at a time. Existing installed dependency directories are temporarily linked for the proof, then removed before hashing; no source or data is borrowed. No packages are installed by the exporter. If tsx hits the documented Windows account lookup failure, the copy uses its own `scripts/test-reader.mjs` with Node 24's built-in TypeScript reader. Other reader failures stop the build. This proves the copied source can be checked with the pinned installed tools; it is not a test of a fresh download or a full Windows installation.

Use `node scripts/public/make.mjs --out <empty-folder-outside-project>` for a kept build. A failure removes that attempted copy. Success writes the private `scripts/public/last.json`: time, source commit, counts, checks and every output file hash. The public tree contains no working commit identifier or private record. `node scripts/public/status.mjs` says whether the working commit or files have changed since it was made. A check-only run does not replace the last-made record.

To update a clean separate local public clone, run `node scripts/public/publish.mjs --from <built-folder> --to <clone-folder>`. It checks the successful private record against the tree hashes, scans again with the current private list, requires a clean clone including untracked and ignored files, and rejects any shared commit with the working repository. It replaces working files but leaves `.git` untouched, then lists additions, changes and removals. It never pushes. Adding `--commit "Your message"` makes a local commit using exactly those words and that clone's configured author. Review the diff before a separate manual push. The publisher does not import private history or add attribution to the commit message.

Images still need visual review, licence notices need release review, and installation needs the separate INSTALL guide. A privacy hit or a failed copied test means there is no publishable build. Do not edit a passed tree in place, forge the last-made record, or bypass a failed proof.
